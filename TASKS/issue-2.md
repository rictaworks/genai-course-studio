# #2 最小 scaffold 計画

#1 の環境準備ブランチを基点にします。DB未提供の阻害要因は継続します。

1. API境界・資料区分・起動状態の期待をテストで記述し、実装がない状態で失敗を記録します。
2. Railsのdomain/use-case/adapters境界と固定ヘルス経路、日本語Next.js画面を実装します。
3. DB不要のunit/request/browser検査とビルドを実施します。
4. 許可済みDBがなければ実DB migration・永続ジョブ・独立worker試験は実施できません。DBを代替して成功とは扱いません。
5. 通常レビュー→セキュリティレビュー→ステージング確認→コミット→日本語draft PRの順で進めます。

業務ドメインの今回は検証用 `Probe` のみです。架空識別子、queued/succeeded/failed状態、同一識別子の重複投入抑止を不変条件にします。画面・HTTP・ジョブは用例を呼び、資料の区分判断は純粋なdomain関数に分離します。製品の講座管理・認証・AI・公開は実装しません。
